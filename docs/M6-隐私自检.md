# M6 隐私自检清单

用于在真机上逐项验证指纹、泄露、拦截与无痕行为。每项给出操作步骤与通过标准。

## 1. 指纹一致性
1. 打开 `https://browserleaks.com/javascript`，记录 `navigator.platform`、`navigator.vendor`、`hardwareConcurrency`、`deviceMemory`、`maxTouchPoints`。
   - 通过：`platform` 与 UA 平台一致（Android 为 `Linux armv8l`），`vendor` 为 `Google Inc.`，`hardwareConcurrency` 与 `deviceMemory` 不超过 4，`maxTouchPoints` 为 5。
2. 打开 `https://browserleaks.com/canvas`，只观察是否可读，不做随机化要求。
   - 通过：页面不报 JS 错误，指纹值与 Chrome 桌面/移动差异合理（不出现 WebView 特有字段）。
3. 隐私设置关闭「反指纹基线」后重复第 1 步。
   - 通过：数值回到设备真实值，说明开关生效。

## 2. Referrer / Cookie / HTTPS-Only
1. 先打开任意 https 页面（等页面加载完，注入的 meta 生效），再从该页点击链接跳到 `https://browserleaks.com/http-headers`。
   - 通过：`Referer` 只保留源（`https://host/`），不带完整路径与查询串。
   - 说明：策略以页面级 meta 注入实现，页面首个导航请求仍可能沿用服务端默认策略。
2. 打开任意含第三方图片的站点，进入隐私设置确认「阻止第三方 Cookie」开启。
   - 通过：站点功能正常，跨站登录态不被复用；白名单站点可单独放行。
3. 地址栏输入 `http://example.com`（HTTP-Only 开关开启）。
   - 通过：先尝试 https；失败弹出提示，可选择「继续 HTTP」或返回，且后续该站点本次会话不再反复弹窗。

## 3. 域名拦截命中与误伤
1. 打开一个广告较多的资讯站，返回隐私设置 → 拦截记录。
   - 通过：能看到被拦截域名、来源页面与时间，计数随浏览增长。
2. 在拦截记录里点按误伤域名 → 「本站不拦截」。
   - 通过：该域名立即进入白名单，刷新页面后不再被拦。
3. 关闭广告拦截总开关。
   - 通过：拦截记录不再新增，页面资源正常加载。

## 4. 无痕零落盘
1. 开启无痕模式，访问 2–3 个页面后强制结束进程，重新打开浏览器。
   - 通过：不恢复无痕标签、历史记录为空、地址栏无上次访问地址。
2. 无痕模式下退出应用。
   - 通过：Cookie、localStorage、会话库均被清理；再次打开不保留登录态。
3. 正常模式访问页面后退出，再以无痕模式进入。
   - 通过：无痕会话不读取、不写入正常会话的标签快照。

## 5. 发布链路
1. 打标签并推送：`git tag v0.9.19 && git push origin v0.9.19`。
   - 通过：Actions 出现 `Release APK` 运行，Release 附件为已正式签名的可安装 APK。
2. 打开 Release 页面。
   - 通过：标题、更新说明、APK 附件齐全，标记为 Latest。
3. 应用内检查更新（设置 → 关于 → 检查更新）。
   - 通过：能读取到最新 Release；无新版本时提示已是最新，有更新时可跳转下载页。
